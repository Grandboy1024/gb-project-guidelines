版本：1.0.0  
适用范围：强制执行

## ADR-001: 采用 ESP-IDF v5.x 与 FreeRTOS 作为核心固件运行环境

- **决策状态**：已确认 (Confirmed)
- **决策背景**：系统需要同时支持 BLE 5.0 高速连接、Wi-Fi/MQTT 云端通信与高频 PWM 调光控制，裸机轮询架构难以满足多任务实时性与网络协议栈的资源要求。
- **决策结论**：统一采用 **ESP-IDF v5.x** 官方框架与原生 **FreeRTOS** 抢占式多任务内核。
- **强制规则**：
  - 合理规划各任务优先级与堆栈深度，核心控制任务必须注册 Task Watchdog Timer (TWDT)。
  - 任务间通信严格通过 FreeRTOS 队列、事件组或互斥量实现，严禁裸全局变量跨任务共享。

## ADR-002: 采用组件化垂直分层与单向依赖架构

- **决策状态**：已确认 (Confirmed)
- **决策背景**：嵌入式固件往往由于驱动、算法与通信代码耦合严重导致移植困难、维护成本高昂且难以进行单元测试。
- **决策结论**：采用 ESP-IDF 标准组件化架构，按 `bsp`、`drivers`、`lighting_engine`、`protocols`、`ota_manager`、`storage` 垂直解耦。
- **强制规则**：
  - 依赖关系必须保持严格单向向下流动：Application $\to$ Protocols / Engine $\to$ Drivers / BSP $\to$ OS / HAL。
  - 核心算法（Gamma、CCT）必须抽离为纯 C 模块，与底层具体硬件引脚彻底解耦，以便支持 Host 端单元测试。

## ADR-003: 严格对齐《BLE API 规范》大端序与 31 字节主广播契约

- **决策状态**：已确认 (Confirmed)
- **决策背景**：iOS 系统不向 App 暴露真实蓝牙 MAC 地址且后台扫描依赖广播中的 Service UUID；跨端多字节整型若字节序不一致将导致协议解析错乱；简单的固定单字节 MAC 异或（`^ 0xAD`）不具备实际安全性。
- **决策结论**：BLE GATT 协议严格执行《BLE API 规范》，31 字节主广播携带 `Flags`、`0xFF77` Service UUID 与 `0xFF` 厂商自定义数据（内含 `DeviceID[2..7]` 截取的 `DeviceID_Short`、`CAP`、`STATE` 与 `StateSeq`），应用层多字节整型严格采用**大端序 (Big-Endian)**，广播 `CID` 采用 Bluetooth SIG 标准**小端序**。
- **强制规则**：
  - 31 字节主广播必须严格满足 `3B Flags + 4B UUID16 (0xFF77) + 24B Manufacturer Data (0xFF)` 布局，禁止私自直接用 `raw_mac ^ 0xAD` 替代 `DeviceID_Short`。
  - PID（功能能力）与 ModelID（外观款式）在固件中彻底解耦，同硬件平台共享同一固件镜像；`CID` 量产必须使用 SIG 正式分配值（联调测试暂用 `0xFFFF`）。

## ADR-004: 采用 A/B 双分区与 YBOT 签名防回滚 OTA 空中升级机制

- **决策状态**：已确认 (Confirmed)
- **决策背景**：单分区在线升级或未经验签的固件若在断电或网络中断时极易导致设备永久损坏（变砖）。
- **决策结论**：统一采用 **A/B 双 App 分区 (`ota_0` / `ota_1`)** 容灾架构，固件打包遵循统一的 **YBOT 二进制信封格式**。
- **强制规则**：
  - 升级前必须校验电量 ($\ge 30\%$) 与硬件兼容掩码；写入完毕校验 Tail CRC32 与 ECDSA-SHA256 签名。
  - 升级重启后必须执行硬件自检并主动确认有效，异常崩溃时 Bootloader 必须能自动回滚至先前正常分区。

## ADR-005: 采用硬件定时器 LEDC 高频 PWM ($\ge 20\text{kHz}$) 与 Gamma 2.2 调光

- **决策状态**：已确认 (Confirmed)
- **决策背景**：软件延时调光会占用 CPU 且容易产生人耳可闻噪声和手机摄像频闪条纹；人眼对亮度的非线性感知会导致低亮度调节突兀。
- **决策结论**：PWM 调光统一由芯片底层 **LEDC 硬件定时器驱动**，载波频率 $\ge 20\text{kHz}$，位深 13-bit；引入 **Gamma 2.2 查找表 (LUT)** 映射。
- **强制规则**：
  - 开关灯与亮度调节必须使用硬件渐变平滑淡入淡出 (Fading)，严禁硬性突变。
  - CCT 双色温调节必须采用恒功率混色算法，确保过渡期间总光通量恒定。

## ADR-006: 严格执行内存静态化与零主循环频繁 malloc 铁律

- **决策状态**：已确认 (Confirmed)
- **决策背景**：嵌入式系统 RAM 极小，频繁动态申请/释放堆内存是产生内存碎片和系统运行数周后 OOM 崩溃的主因。
- **决策结论**：核心数据结构、任务堆栈、通信缓冲区一律采用**静态内存分配 (Static Allocation)** 或预分配环形缓冲区。
- **强制规则**：
  - 严禁在主业务任务循环、高频定时器回调或 ISR 中调用 `malloc()` / `free()`。

## ADR-007: 统一 ESP_LOG 结构化分级日志与 Flash Core Dump 故障转储

- **决策状态**：已确认 (Confirmed)
- **决策背景**：裸用 `printf()` 缺乏日志过滤且同步输出阻塞严重；设备在线上发生偶发 Crash 时无法定位崩溃堆栈。
- **决策结论**：统一使用 ESP-IDF 标准 `ESP_LOGx` 宏输出；配置 Flash 分区记录系统 Panic 时的 Core Dump 上下文。
- **强制规则**：
  - 严禁在中断上下文 (ISR) 中输出日志；生产环境构建将日志过滤级别收敛至 `INFO`。
  - 固件初始化必须检查 `esp_reset_reason()`，遇到异常复位主动上报遥测诊断日志。

## ADR-008: 全局 Task Watchdog (TWDT) 监控与 NVS 磨损防抖机制

- **决策状态**：已确认 (Confirmed)
- **决策背景**：任务死锁会导致设备失去响应；用户连续滑动调光若每次都写入 Flash 将在短期内消耗掉 Flash 物理擦写寿命。
- **决策结论**：主业务任务全部接入 Task Watchdog Timer (TWDT)；状态持久化采用 **2 秒防抖定时器** 落盘。
- **强制规则**：
  - 关键任务按时喂狗，禁止使用空死循环阻塞任务。
  - 调节亮度、色温等高频操作必须经 2 秒防抖后方可写入 NVS。
